# Trello Connect · AstrBot 插件

把聊天消息变成可执行的 Trello 待办：**中文触发 → AI 整理 → 预览 / 多轮修改 → 明确确认 → 创建卡片**。

支持任务描述、记录时间、截止时间、任务清单和重要图片附件。所有卡片统一进入所选看板的 `reminder` 列表。

> 确认前不会创建 Trello 列表、卡片、清单或上传附件；但任务文字和图片会在生成草稿时发送给当前会话的模型服务。请勿发送未经授权的敏感资料。

## 功能

- **中文模糊触发**：识别“创建代办”“帮我创建待办”“创建trello卡片”“把这条消息放到trello”等请求，不必记完整命令；也提供 `/trello` 显式命令。
- **AI 总结任务**：使用 AstrBot 当前会话的聊天模型生成标题、完整任务描述和 1～20 项任务清单，无需额外配置模型密钥。
- **自动记录时间**：写入草稿建立时间；从消息中提取有依据的截止时间。只有日期、没有具体时刻时会先询问，不擅自补截止时刻；没有截止要求则不设置。
- **多轮修改再提交**：直接回复“截止时间不对，改到周五18点”“标题改成季度汇报”等意见；每次成功修改都会生成新的确认编号。
- **图片附件**：支持当前消息、可读取的引用消息，以及草稿期间追加的图片；视觉模型选择重要图片，也可按编号明确指定。只把最终草稿选中的图片上传 Trello。
- **固定目标**：在插件配置中填写 API Key、用户 Token、工作区和看板；正式确认时自动复用或创建 `reminder` 列表。
- **防止重复创建**：每个用户、每个会话独立草稿；确认绑定最新版本；持久化提交回执。超时结果不明时停止重发，提供只读核对。

## 环境要求与安装

- AstrBot **4.5.7 或以上**，Python **3.10 或以上**，并已配置可用的聊天模型。
- 图片内容自动理解需要模型和提供商支持视觉；纯文本模型可以手动选择附件。
- AstrBot 运行环境能直接访问 `api.trello.com`、模型服务及图片来源。本插件的 Trello / 图片 HTTP 客户端不自动采用系统代理环境变量。

在 AstrBot 插件管理中选择从 GitHub URL 安装：

```text
https://github.com/VellowK/astrbot_plugin_trelloconnect
```

安装后在插件设置中填写授权信息。依赖见 [requirements.txt](requirements.txt)。手动安装时把项目放入 AstrBot 的 `data/plugins/astrbot_plugin_trelloconnect` 目录，并在 AstrBot 所用的 Python 环境执行：

```bash
python -m pip install -r data/plugins/astrbot_plugin_trelloconnect/requirements.txt
```

然后重载插件。Windows 上的时区数据由 `tzdata` 提供。

## 首次配置：API Key + 用户 Token

支持 **点击链接授权**，但不是“授权后自动登录”：需要先申请自己的 API Key，再把授权页面显示的 Token 手动填入插件设置。当前版本没有 OAuth 回调接收页面，不会自动回填或续期 Token，也无需提供 Trello 账号密码 / Application Secret。工作区和看板通过 ID / 链接配置，不提供动态下拉选择。

1. 登录 **[Trello API Key 申请 / 管理地址](https://trello.com/apps/admin)**，创建或选择一个 Power-Up，在 **Trello Auth / API Key** 页面生成 Key。旧版 [Power-Up 管理地址](https://trello.com/power-ups/admin) 也可作为入口。
2. 在 AstrBot 插件设置填入 `api_key`，保存并重载。以 **AstrBot 管理员身份私聊** Bot，发送：

   ```text
   /trello 授权
   ```

   **v0.1.2 起，管理员私聊直接发送 `/trello` 或 `/trello 帮助` 也会附上同样的授权引导；群聊和普通用户的帮助不会包含个人授权链接。** 保存 Key 后请重载插件；如果仍未显示链接，先确认插件已更新、发送者已配置为 AstrBot 管理员且当前为私聊，再尝试 `/trello 授权`。不要发送 Key / Token 排查。

   Bot 会生成包含你所配置 Key 的 Trello 授权链接，点击后在 Trello 页面核对账号并允许 **read,write** 权限。默认有效期 **30 天**；不申请 `account` 权限。不需要先填 Token、工作区或看板，也不会调用模型 / 创建卡片。未填 Key 时，该命令会先提供申请地址和步骤；群聊不会返回个人授权链接。

   也可以手动打开以下地址（将 `YOUR_API_KEY` 换成自己的 Key）：

   ```text
   https://trello.com/1/authorize?expiration=30days&name=AstrBotTrelloConnect&scope=read,write&response_type=token&key=YOUR_API_KEY
   ```

   参考 [Trello 官方授权文档](https://developer.atlassian.com/cloud/trello/guides/rest-api/authorization/)。
3. 将 Trello 授权页面显示的 Token 复制到 AstrBot 插件设置的 `token`，保存并重载。**不要把 Token 发给 Bot、提交进 Git，或放进公开截图。** Token 到期或被撤销后，再发送 `/trello 授权` 重新授权并手动更新配置。
4. 以 **AstrBot 管理员身份私聊** Bot，发送 `/trello 工作区`，把选中项目的 ID 填入 `workspace_id`，保存 / 重载。
5. 发送 `/trello 看板`，把所选看板 ID 填入 `board_id`，保存 / 重载。也可以填写 `https://trello.com/b/短代码/看板名` 形式的看板链接。
6. 发送 `/trello 检查`，核对工作区和看板。此命令只读取，不会提前创建 `reminder`；实际写权限以确认提交结果为准。
7. 默认仅允许管理员私聊使用。普通用户需加入 `allowed_users`，例如 `12345678` 或 `平台实例ID:12345678`；群聊还需开启 `enable_group`。

> 一个插件实例共用一组 Trello 凭据，所有获准用户都在该账号权限下操作，不是每个聊天用户独立登录。Trello 账号必须能够在目标看板创建列表、卡片、清单和附件。

## 使用示例

### 直接创建与修改

```text
你：帮我创建待办：明天下午3点前交季度报告，先整理销售数据，再审核，最后发给负责人。
Bot：Trello 待确认草稿（ABC123-1）
     目标：我的工作区 / 项目看板 / reminder
     标题、记录时间、截止时间、描述、任务清单、将上传的图片……
你：截止时间不对，改成后天下午4点，标题改成季度销售报告。
Bot：更新后的待确认草稿（ABC123-2）……
你：确认创建 ABC123-2
Bot：已创建 Trello 卡片。
     卡片已存在：https://trello.com/c/……
```

请使用 **Bot 实际返回的最新编号**，单独回复 `确认创建 编号`。只回复“确认 / 没问题 / 可以了”会提示完整确认方式，不会提交。旧版本编号无效；确认消息若附带新图片，会要求先修改草稿。

没有明确截止时间时可以直接创建，不强迫填写；如果时间有歧义，须先回答草稿里的问题，也可以说“不设置截止时间”。所有时间以 `timezone` 配置为准，默认 `Asia/Shanghai`。模型可能理解错误，提交前请自行核对。

### 引用、后续消息与图片

- 引用一条任务消息后发送“创建trello卡片”；插件读取适配器实际提供的引用正文和图片，不主动抓取聊天历史。
- 先发送“创建代办”，再在下一条消息中发送任务正文和图片。
- 在已有草稿时直接追加图片，或说“附上第1张和第3张图”“不要上传图片”。编号在预览中显示，追加后仍须重新确认。
- 视觉请求报错时会尝试纯文本整理并提示；也可关闭 `vision_enabled`。此时请明确指定附件编号，并用文字补充图中要求。某些提供商可能静默忽略图片，插件不能保证检测到这种情况。

**草稿期间，同一用户在同一会话发送的非命令消息会被视为修改意见。** 想转回普通聊天，请先回复“取消”或完成提交。其他插件的 `/...` 指令不会被当作修改意见。

## 命令

| 命令 / 文本 | 作用 |
| --- | --- |
| `/trello`、`/trello 帮助` | 查看帮助；管理员私聊时同时提供授权引导，已填 Key 时直接附上授权链接 |
| `/trello 创建 任务正文` | 创建待确认草稿，可同时附图片 |
| `创建待办：任务正文`、`创建代办：任务正文`、`创建trello卡片：任务正文` | 自然语言创建 |
| 直接发送修改意见 / 追加图片 | 修改当前草稿 |
| `确认创建 最新编号`、`/trello 确认 最新编号` | 正式提交，必须对应当前用户、会话及草稿版本 |
| `取消`、`/trello 取消` | 删除本地草稿和缓存图片，不删除已提交卡片 |
| `/trello 状态` | 查看当前草稿，或最近一次提交回执 |
| `/trello 核对` | 对结果未决的提交只读核对，不自动补写 |
| `/trello 授权`、`/trello 登录`、`/trello auth` | 仅管理员私聊：提供 Key 申请地址；已填 Key 时生成授权链接，Token 需手动填入设置 |
| `/trello 工作区` | 管理员查询当前授权账号的工作区，最多显示前 50 项 |
| `/trello 看板` | 管理员查询已配置工作区下开放的看板，最多显示前 50 项 |
| `/trello 检查` | 管理员检查授权可读性、工作区 / 看板归属 |

自然语言只对常见的**开头创建请求**做规则匹配，不扫描全部聊天让模型猜测意图。“不要创建待办”“你知道怎么创建trello卡片吗”等普通提及不会触发；未覆盖的说法请用显式命令。草稿修改阶段仍会接收普通文字。

## 配置项

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `api_key` / `token` | 空 | Trello API Key / 用户 Token；非 GitHub Token |
| `workspace_id` | 空 | 工作区 ID 或短名称 |
| `board_id` | 空 | 看板 ID、短代码或 `https://trello.com/b/...` 链接，必须属于指定工作区 |
| `timezone` | `Asia/Shanghai` | IANA 时区，用于记录时间和日期理解 |
| `allowed_users` | `[]` | 普通用户允许列表；管理员始终可用；空列表仅管理员可用 |
| `natural_language` | `true` | 允许中文开头创建请求；关闭后使用 `/trello 创建` |
| `vision_enabled` | `true` | 把草稿图片发给当前会话模型识别；关闭后手动选附件 |
| `enable_group` | `false` | 允许群聊；回复、草稿和卡片链接会公开到原群 |
| `group_require_at` | `true` | 群聊首次自然语言创建需要 @ / 唤醒；显式命令、已有草稿后续消息不受此限制 |
| `draft_timeout_minutes` | `20` | 草稿 / 等待后续消息的空闲超时，5～120 分钟；重载 / 重启也会失效 |
| `max_images` | `5` | 每份草稿最多图片数，1～10，包含未选中的图片 |
| `max_image_mb` | `5` | 单张图片大小上限，1～10 MiB，也受模型和 Trello 账号限制 |
| `max_active_drafts` | `20` | 同时保留的本地交互状态上限，1～100 |
| `request_timeout` | `40` | 单次 Trello / 图片请求超时，10～120 秒 |
| `model_timeout` | `90` | 单次模型请求超时，15～180 秒；视觉失败降级会再调用一次 |
| `model_cooldown_seconds` | `2` | 同用户、同会话连续整理的最短间隔，0～60 秒 |
| `allow_private_images` | `false` | 允许图片组件下载内网地址，高风险；只在信任适配器和来源时开启 |

每份草稿最多成功修改 30 次。标题不超过 160 字，描述不超过 6000 字，清单每项不超过 240 字；单次任务或修改文本不超过 12000 字。

## 提交失败、防重复与恢复

Trello 的“创建卡片 → 添加清单 → 上传图片”不是一个原子事务，本插件**不承诺 exactly-once**，也不对写请求自动重试。

- 正式确认时重新验证目标归属，复用同名列表（忽略大小写、首尾空白），没有时才创建 `reminder`。多个同名列表会阻止提交，需先整理。
- 提交前写入本地回执；收到卡片 ID 后立即保存链接，再写入任务清单和选中图片。同一进程使用互斥锁避免并发创建列表，但多进程 / 多实例并不共享此锁。
- 如果卡片已经创建，但清单 / 图片写入失败，会返回卡片链接并提示手动补齐，**不会再创建一张卡片**。取消草稿也不会回滚远端写入。
- 遇到超时、连接中断、服务端异常或进程中断，可能无法判断是否已创建。此时锁定本用户、本会话的继续创建，先执行 `/trello 状态`、`/trello 核对`。
- 核对通过卡片描述中的 `astrbot-operation:...` 查找原看板，包括归档卡片；找到后返回链接，并提示检查清单和附件，不自动补写。
- 查不到**不代表没有创建**：卡片可能刚创建、被移动出看板、被删除 / 修改过描述，或看板过大无法完整读取。请手动检查操作编号及内容。
- 只有人工确认没有旧卡片后，才使用核对返回的 `/trello 清除未决 操作编号末8位`。清除只移除本地锁定，不删除远端内容，操作不当可能造成重复。

回执保留在 AstrBot 数据目录的 `plugin_data/astrbot_plugin_trelloconnect/receipts`，每个用户 / 会话仅保存最近一次结果。删除该目录、跨实例运行、手动清除、磁盘故障、远端操作和极端崩溃都可能影响防重保护。

## 隐私、安全与限制

- Trello 凭据由 AstrBot 保存到本地插件配置；插件不实现额外加密。请限制配置文件、备份、日志和 WebUI 的访问权限，及时撤销泄露或闲置 Token。
- 模型仅接收本次任务正文、可用引用内容、上次草稿、修改意见及本草稿图片，不主动读取完整聊天记录；不把 Trello Key / Token 放进模型提示词，也不给整理调用提供执行工具。
- 开启识图时，**所有草稿图片**可能发送给模型以判断重要性；明确确认后，**仅最终选中的图片**上传 Trello。描述和清单以最终预览为准，原文不另行整段备份到卡片。
- 本地图片暂存于数据目录的 `plugin_data/astrbot_plugin_trelloconnect/images`，取消、提交完成、超时或正常卸载时清理；异常退出后的遗留文件在下次加载后按超时清理。缓存不是加密存储，请保护磁盘和备份。
- 图片支持 PNG / JPEG / GIF / WebP 的内容签名及大小检查，不做恶意内容扫描或完整图像解码。不从纯文字链接或路径任意抓图，只处理适配器提供的 `Image` 组件；本地组件路径属于可信适配器边界。
- 默认阻止私网、回环、链路本地图片地址及解析到非公网的域名；重定向也会校验。不支持远程文件共享路径。不要为了普通公网图片随意开启内网下载。
- 群聊默认关闭；开启后必须谨慎配置允许用户。任何获准用户创建的卡片均使用同一个 Trello 账号，其链接的可见性还取决于看板权限。
- 草稿只保存在内存中，不跨重启恢复；提交回执持久化但不保存任务正文和图片。引用内容依赖平台适配器，未提供时请手动转发正文 / 图片。
- “reminder”是列表名称，不是定时调度器：插件会设置明确的卡片截止时间，但不配置 Trello 的 `dueReminder`，也不提供 Bot 定时提醒、同步、删除或更新已有卡片功能。模型整理结果需人工核对。

## 开发与测试

```bash
python -m pip install -r requirements.txt
python -m unittest discover -v
# 可选开发工具，不是运行时依赖：
python -m pip install ruff
python -m ruff check .
python -m ruff format --check .
```

当前有 **92 项自动化测试**，涵盖帮助入口授权引导 / 参数编码 / 管理员私聊限制、中文触发、草稿校验、权限 / 会话隔离、版本确认、并发防重、异常回执、工作区归属、列表复用、API 错误脱敏、分页核对、图片大小 / SSRF / 重定向、模型视觉降级和当前模型接口。另有本机 loopback HTTP 夹具实际验证流式响应、图片下载和 multipart 上传，不访问真实 Trello。

测试使用最小 AstrBot SDK 替身和模拟 API / 模型；**尚未使用真实 Trello 凭据与运行中的 AstrBot 做端到端联调**，不等同于平台兼容性或模型识图准确率保证。

主要模块：[main.py](main.py)（消息流程）、[summarizer.py](summarizer.py)（当前模型整理）、[trello.py](trello.py)（API）、[submission.py](submission.py)（提交回执与防重）、[images.py](images.py)（图片暂存）、[intent.py](intent.py)（意图匹配）。
